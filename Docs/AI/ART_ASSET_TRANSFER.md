# Unity 美术素材交接规则

适用对象：项目负责人、学生、Unity 制作人员，以及未来接手的 Codex、Claude 或其他 Agent。

## 默认流程

1. 任务开始先检查 Unity 工程是否已包含所需素材。若已预先复制到工程，直接使用并核对文件名、尺寸、格式与版本；不要重复复制，也不需要为拿素材去 GitHub 下载。
2. 若缺文件或文件损坏，向项目维护者发一份精确请求，包含：设计仓库相对路径、用途、目标 Unity 路径、要求的格式/版本。不要只说“缺素材”。
3. 维护者把获准的文件放在设计仓库 `TechnicalArt/unity_drop/<日期_任务名>/`，通过双方可访问的共享网络目录通知 Unity 制作端。
4. 从本机可访问的共享根目录解析该相对路径，只复制所需文件到 Unity 工程。不要移动、删除、改名或编辑共享目录中的源文件。若确需图像处理，另存为新文件并保留源文件。
5. 在任务交接或 `Docs/CH1_UNITY_PROGRESS.md` 记录复制的文件清单、来源版本、Unity 目标目录，以及导入/验证状态。

## 渠道与路径

- 设计仓库是美术源文件和批准资产的权威来源。`TechnicalArt/unity_drop/` 是按任务临时交接的 staging 目录；目录名应带日期和任务名。
- GitHub 用于仓库同步、审阅和备份，不是 Unity 制作端索取美术文件的默认渠道。Unity 仓库正常提交、推送不受此规则影响。
- 网络盘符、挂载点和主机名因电脑而异。文件说明使用仓库相对路径；接手者根据本机已配置的共享文件夹找到该仓库。不要要求所有人使用某个维护者专属盘符或电脑名。
- 共享网络暂不可用时，先将精确缺料清单交给维护者，等待其指定临时替代交付方法；不要自行从 GitHub、聊天附件或旧版本目录挑一个“看起来一样”的文件。
